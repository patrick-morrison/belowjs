Model Comparison

Patrick Morrison, 24 April 2026

The Model Comparison example is a desktop tool for aligning two GLB models, checking how well they match, inspecting their differences, and exporting the aligned result as a new GLB.

It is useful when you have two versions of the same object or site and need to bring them into the same frame before inspecting what changed. That might be a cleaned mesh against an original capture, two photogrammetry reconstructions of the same wreck, or a survey model against a reference export.

Like the other BelowJS examples, this page does two jobs: it shows what can be built on top of the core viewer, and it provides a genuinely practical tool you can use immediately.

Typical uses include:

  • a cleaned mesh against an original capture
  • before and after processing passes
  • two photogrammetry reconstructions of the same subject
  • a survey model against a reference or CAD-derived export

1. Load the models

Open the Model Comparison example and load one GLB into each pane. The viewer starts in split mode, which is the right place to begin because both cameras stay linked while you orbit around the same features on each model.

At this stage, decide which model should stay fixed. In most cases this is the cleaner or more trusted reference. You can switch the fixed model with Ref: A / Ref: B.

2. Add matched points

Right-click to place control points on recognisable features in each model. The goal is not to place a lot of points, but to place a few good ones that are easy to identify on both surfaces.

Good points are spread across the object rather than clustered in one corner. Corners, holes, sharp edges, and distinctive damage patterns work well. Flat or repetitive regions usually do not.

The point list updates live as you work. Matching names are what define a pair, so duplicate names are treated as an error until you resolve them.

3. Solve the alignment

As soon as you have three valid pairs, the example computes a marker-based similarity transform. The RMS readout and residual lines give you a quick sense of whether the fit is believable.

Once the marker solve is reasonable, click Refine to run the geometry-based pass. This starts from your control points and improves the result using the surfaces themselves. It is a good way to tighten an already sensible alignment, but it is not a substitute for bad point placement.

If you want the full numbers, click Method…. That report includes the solve method, matched pair count, residuals, and transform values.

4. Inspect the result

After the fit, hit Z to move from split mode into the combined view. The default combined mode is a single-model view, which makes it easy to toggle between the aligned models and check the result quickly.

From there you can switch between the other inspection modes:

  • Single: shows one model cleanly for inspection or screenshots
  • X-Ray: helps check broad overlap between the two meshes
  • Diff: tints the surfaces separately to reveal offsets and intersections
  • C2C: computes nearest-surface distance from one model to the other

The C2C view uses a white-to-red distance ramp, where white is near-zero difference and deeper red shows larger offsets. The visible range slider trims the display so you can focus on the useful part of the distribution rather than the full long tail.

5. Export the aligned model

Once you are happy with the result, export the moving model as a new GLB. The exported file is just a normal model again, so you can open it in the Basic Viewer, the Drag & Drop example, or your own BelowJS setup.

npm run dev:model-comparison
npm run dev:basic

A common workflow is to align the moving model in Model Comparison, export the aligned GLB, and then use that exported result in a normal viewer for presentation, delivery, or further annotation.

Other options

Save and load point sets

You can save your point set as JSON and load it again later. This is useful if you want to continue a session, share control points with someone else, or compare several processed versions against the same reference.

The save file remembers which model was the reference and preserves the saved transforms, so it still restores correctly even if the same models are loaded into A and B in the opposite order next time.

Screenshots

The screenshot button captures the view you are actually looking at, whether that is split, single, X-Ray, Diff, or C2C. For most documentation, three images are enough:

  1. split view with both models loaded and a few matched points visible
  2. combined C2C view with the visible distance range trimmed to the part you want to discuss
  3. the exported aligned model opened in a normal BelowJS viewer

If you want one extra technical image, capture the Method… dialog after refinement so the RMS and transform are recorded alongside the visual result.

Practical notes

  • Use desktop. The comparison tool is intentionally blocked on small screens.
  • Use C2C after the marker solve is already reasonable.
  • If one model is only a partial reconstruction, trust the point solve first and treat refinement carefully.
  • If the result looks wrong, the usual cause is poor or unevenly distributed control points.

Next steps

Ready to compare two models? Open the Model Comparison example and start with three clear matched points on well-separated features. If you need the exported result elsewhere, drop it straight into another BelowJS viewer.
